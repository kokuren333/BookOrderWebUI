# Image style (generated illustrations that belong to the book)

Generated images must look like they were commissioned for this book, as one series, in the same design language
as its type, colour and pages. Write the style sheet after the design direction is agreed, before any image is
generated (images are generated in the design stage, after the design phase).

## When to use generated images at all

Only for illustrative, decorative or conceptual roles the StyleBible allows (chapter openers, part pages, concept
illustrations). Data, processes, comparisons and anything factual stay charts, diagrams or tables drawn from data.
Few, consistent images beat many different ones; leave a slot as typography if an image would not add meaning.

## plan/image-style.md

```markdown
# Image style — <book>

## Derived from
Design direction <name>; palette from plan/style-bible.yaml; reference books <ids> (what we take from them).

## Medium and rendering
e.g. flat vector shapes with a slight risograph grain / fine ink line with one flat tint / soft gouache washes.
Line weight, edge quality, level of detail, perspective (flat / isometric / natural), lighting.

## Palette use
Which palette roles appear (e.g. accent for one focal element only, secondary_accent for large areas, tints of
both toward the paper colour #F8F6F1); maximum number of hues; no gradients / no neon / no pure black.

## Background and edges
Paper-coloured background matching the page (or transparent); no frames, no drop shadows, no vignette;
how the image meets the margin (bleed / boxed / free-standing).

## Composition
Negative space for the caption side; focal point position; scale of objects; consistent viewpoint across the set.

## Never
Text, letters, numbers, logos, watermarks; photorealistic faces; recognisable brands or artworks; fake charts or
data; styles of named living artists.

## Prompt prefix
<3–6 sentences that state all of the above compactly. This exact text is sent with every image request.>
```

## Anchor, generation, review

1. `bookorder images samples` → three candidates in design/image-samples/; look at them with the user next to the
   proof pages; `bookorder images anchor design/image-samples/sample-N.png`. Every request references the anchor.
2. Images are generated by `bookorder goal` in asset_generation through the Codex provider
   (project.json `image_generation.provider: "codex"`), bound to the style sheet and anchor.
3. The `image-review` task: proofs/images.html shows the series with palette-conformance scores; regenerate
   outliers by refining their request, or revise the style sheet if the whole set drifts (that regenerates all).
4. The style sheet and anchor are part of the approved design: changing them needs the user's approval again.
