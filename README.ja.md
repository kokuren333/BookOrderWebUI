# BookOrder WebUI

BookOrderは、本の企画をAI Agentに渡せるポータブルな出版ジョブにまとめるブラウザアプリです。本の目的や読者、資料の役割、出版形式を入力すると、調査・構成・執筆・編集・組版・検証に使う指示やツールをZIPにまとめます。

> English guide: [README.md](README.md)

## WebUIの使い方

1. 公開済みの静的サイトを開くか、[ローカルで起動](#ローカルで起動)します。
2. **Quick** または **Advanced publishing** を選びます。
3. 書名、目的、対象読者、言語、希望する分量を入力します。
4. URLやファイルを追加し、推定された役割を確認・修正します。
5. 本固有の希望を「本全体への優先指示」に自分の言葉で書きます。この指示はジョブ全体の工程でAgentに渡されます。
6. 必要ならAdvanced publishingで、出版物の構成、根拠・調査方針、引用・参考文献、出力、判型、レイアウト、デザインを指定します。
7. Agentを実行するマシンのOSとCPUを選び、Publishing Job ZIPをダウンロードします。
8. ZIPを展開し、`publishing-job`フォルダーをファイル操作ができるAI Agentで開きます。`AGENTS.md`を読んでジョブを完了まで実行するよう依頼してください。Codexの場合は生成されたタスクに`/goal`コマンドが記載されています。

WebUI自体はAgentを実行せず、URLのページも取得しません。ダウンロードしたジョブをAgentに渡した後、Agentが調査します。

## QuickとAdvanced

**Quick**では、本の企画、資料、指示、希望分量、出力、実行環境を中心に入力します。資料の役割は推定され、必要に応じて編集できます。構成・図表・引用方法は、目的と指示からAgentが設計します。

**Advanced publishing**では、出版物タイプと副タイプ、構成モード（AUTO / GUIDED / FIXED）、章ごとのブロック方針、演習・図表方針、資料の権威性と用途、調査設定、引用・参考文献の形式、出版形式・デザインを細かく指定できます。Agentに判断を任せる項目は自動のままにできます。

「本全体への優先指示」には、語り口、難易度、説明の深さ、扱う・扱わないテーマ、章構成、事例、図表にしたい内容などを書きます。入力した文面はそのままAgentに渡されます。分量、出力形式、判型など対応する構造化設定は、各設定欄での選択が優先されます。

## 資料の役割と引用

ファイルとURLには共通のSource Role Systemを適用します。URLは1行に1件ずつ貼り付けます。URLごとに役割カードが作られ、個別編集または選択したURLの一括編集ができます。役割の「推定」は後から変更できます。

| 役割 | BookOrderでの使い方 | 成果物での扱い |
|---|---|---|
| `evidence`（根拠） | 事実・定義・数値・推奨の根拠として本文で引用できます。 | 使用した場合、本文citationと引用文献に掲載。 |
| `background`（執筆時の参考） | 内容理解、観点、現場の経験、テーマ探索に使います。 | 本文では引用せず、巻末一覧にも掲載しません。執筆時のみ参照。 |
| `further_reading`（読者向け参考資料） | 読者に明示的に紹介したい資料です。 | 本文では引用せず、読者向け参考資料一覧に掲載。 |
| `structure_reference`（構成参考） | 章の順序や説明の組み立てを考える参考にします。 | 本文では引用せず、巻末にも掲載しません。 |
| `layout_reference` / `style_reference` / `visual_reference` | レイアウト、文体、見た目の参考にします。事実の根拠にはしません。 | 文献一覧には掲載しません。 |
| `redraw_source`（再作図元） | 実際に作成・翻案する図表の元資料です。 | 図表を成果物で使用した場合に限り、図表出典として掲載。 |

1つの語句や資料ロールだけで資料の信頼性・文章の性質を断定しません。Advanced publishingでは、各資料について権威性（authority）、本文引用の可否、使用する章、用途、メモを追加できます。ただし、citation設定を変更しても`background`を引用可能にはできません。

本文での引用形式と巻末リストの書式・グループ分けは別々に設定します。事実の根拠として使った`evidence`は引用文献に掲載します。`background`は執筆時の参照にとどまり、読者向け一覧に出るのは`further_reading`に指定した資料だけです。

## 出版ジョブのアーキテクチャ

WebUIは入力をZIPにまとめ、展開後のジョブはAI Agentが実行します。BookOrderのintent-driven architectureは固定の章テンプレートに本文を流し込むのではなく、ユーザーの意図、読者、出版物タイプ、資料の役割から本ごとの構成を設計します。

- **Research**：提供資料を取り込み、許可されている場合は追加のWeb調査を行います。ユーザー提供資料とAgentが見つけた資料に同じ役割・引用ルールを適用します。
- **Publication planning**：本全体の構成と章ごとのブロックを計画します。AUTO / GUIDED / FIXEDで、自動判断とユーザー指定の範囲を調整します。
- **Drafting and editing**：章ごとのMarkdown原稿を作成し、citation、相互参照、図表と資料情報を結び付けます。
- **Audit and QA**：資料ロール、citation、構成、図表、指定出力を検査します。
- **Build and validation**：選択された形式を生成して検証します。必要な出版ゲートを満たしてから成果物をパッケージします。

編集可能な正本は章ごとのMarkdownとプロジェクトのメタデータ・素材です。PDF、DOCX、HTML、EPUB、静的サイトは出力物であり、正本の代わりにはなりません。

## データの扱い

ファイルはブラウザ内で処理してZIPに含めます。BookOrderのサーバーへのアップロードや、アカウント・データベースへの保存はありません。ZIPには本の指示や資料が含まれるため、安全に保管してください。同梱ランタイム、ライセンス、Agentの実行については、WebUI内の「安全性・データの扱い」ページを確認してください。

## ローカルで起動

```sh
npm ci
python tools/prepare-runtimes.py
npm run dev
```

`http://127.0.0.1:5173`を開きます。ランタイム準備コマンドは、生成ジョブに同梱するランタイムをダウンロードします。`npm run build`は静的サイトを`dist/`に生成します。静的ホスティングのパス配下に配置する場合は、たとえば`npm run build -- --base=/repository/`のようにViteのbaseを指定します。
